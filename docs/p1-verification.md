## 已交付的闭环

- 欢迎页与独立研究详情 `#/research/{id}` 分开；详情呈现排队、运行、完成、失败和取消状态、真实阶段事件、结果阅读区及本任务证据。失败重试创建新任务并保留旧记录，可以修改问题或导出结果。
- 资料库与本次证据分开。资料支持繁简标题、编纂者、人物、主题、类型和索引状态筛选，分页浏览、元数据编辑、完整原文及页内查找。
- 引用按保存位置高亮连续摘录，使用 Unicode code point 偏移；可展开前后文、查看快照版本与来源，并列对照两份已读证据。不用并列数量推断来源独立性。
- 上传后自动进入独立索引 worker；MySQL 保存进度和租约，Redis 负责投递，Milvus 按稳定片段 ID 幂等 upsert。详情可查看批次进度、脱敏错误和重试，不再要求用户执行手工索引命令。
- 维基文库官方目录检索、固定修订正文读取与复用已实现。当前本机配置选择 `SEARCH_PROVIDER=wikisource`，范围仅限该站，未冒充通用网页搜索；Tavily 仍可另行配置。
- 评测页面显示真实批次、逐题回答、证据、模型审核和独立人工评分表单。人工分数保持空白，尚无独立人工质量评分。

模型为本机环境配置实际返回的 `deepseek-flash`。模型、BGE 标识、8 份资料正文哈希、预算及执行时核心代码哈希保存在 [实验清单](p1-manifest.json)。三方案均为 local，同一台机器顺序执行，每题每方法一次；RAG 和 Agent 使用同一回答与引用检查流程。扩充的两卷在 90 条记录保存完毕后才导入。

Agent 有 22 条 partial、6 条 answered、1 条 insufficient_evidence 和1次执行失败；RAG有18条 answered、9条 partial、3条 insufficient_evidence。这些是本次证据覆盖状态，不是人工准确率。程序定位检查与模型支持审核均不能替代人工。费用无价格配置，全部保留 null。

完整汇总见 [原始指标](p1-report.json)；[90 条完整记录与执行时核心源码 ZIP](p1-evaluation.zip) 可离线核查。网页读取的原始文件存放在 `evaluation-data` 持久化卷。评测后只细化了结构化失败的异常类型和恢复文案，未更改提示词、重试预算或结果；ZIP 中 `implementation/` 保存实验执行时版本，以清单哈希为准。

## 公开失败与不足案例

- [Q12 Agent：执行失败](p1-cases/Q12_agent.json)。Answer.format_retry 请求后抛出 ValueError，9次已记录模型调用共54,782 Token。没有补写回答或替换成另一次成功结果。
- [Q01 RAG：未形成核心结论](p1-cases/Q01_rag.json)。已知锚点读取0/1，最终为证据不足，不能把检索过一次理解为已经找到并读懂所需资料。
- [Q11 Agent：锚点读取0/2](p1-cases/Q11_agent.json)。存在其他已读资料与部分回答；这个结果仅说明已知锚点未覆盖，是否有等价证据仍需人工核查。
- [Q19 Agent：解释与原文冲突](p1-cases/Q19_agent.json)。实现者的 **AI 抽查**发现回答写“同日生”，所引原文却是“先祿山一日生，思明除日生，祿山歲日生”；模型支持审核还判为“支持”。这是定位检查通过而解释出错的实际例子，未填入人工评分，也未修改原始结果掩盖问题。

因此当前可以展示资料获取、研究循环、证据追溯、失败恢复与真实评测工程，不能宣传“引用准确率100%”或“Agent回答质量已经优于RAG”。独立人工评分、对数量/人物/时间关系的细粒度核查、合法现代研究语料仍待完善。

## 运行边界

资料列表目前在小规模库的元数据上执行繁简筛选，不加载全库原文；尚未改成大规模中文元数据搜索服务。索引进度表示已提交片段，不是模型下载百分比。所有 worker 长期离线时，需恢复 worker 才会清理过期租约。人工评分界面面向单人本地使用，最后一次提交生效，没有多人评分协同和认证。

未做新的重排器、OCR、近似转载可靠识别、全库爬取、自动史源独立性判定、并发负载/无缓存下载性能测试或独立历史专家审核。
