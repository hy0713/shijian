# 史料策略：全网研究与专题资料库

个人项目不需要先做“全史书数据库”。当前默认全网研究：根据问题用 DeepSeek Search 寻找候选，再用 Fetch 读取正文，保存本次可核查的证据。原有安史之乱资料保留为专题演示库、历史引用与回归语料，不自动加入全网任务。用户明确选择限定资料研究时才检索当前资料库。

本地保存是证据快照与可复核机制，不是要求个人先收齐所有史书。网页结果不等于历史事实：摘要不作证据，版本未知就保留未知，读不到原文就说明缺口；现代资料、数字转录与事件当时记录仍需区分。

在线 P1 在候选上提供机构/学术域名与语种线索，用户可筛选展示；这是可解释的选源提示，不是权威分数、许可判断或史实保证。模型根据问题与缺口安排中英文查询，工具的 `language` 参数只记录查询意图，不是假装搜索服务支持语言过滤。其他语种识别有限，旧任务保留当时的线索。

长网页只向模型返回少量片段 ID、目录及匹配段落。`read_passage(source_id=本任务网页, query=原文关键词)` 可以在已取得全文内重新定位，不再请求 Fetch；自动读取所在节标题及相邻原文，防止日期脱离年份标题。目录仅按明确 Markdown 标题、独立年份行或卷章标题规则识别，展示最多80项；正文搜索仍可到达目录以外的片段。新导入英文长段落沿句末切分，已存在的片段及历史引用不重切。

除规范 URL、同正文哈希去重外，本任务网页之间增加前6万字符的8字符片段 Jaccard 相似提示（阈值0.85、至少120字符）。它不合并原文、不判定抄袭或共同史源，也不是全库近重复检索；短摘录、改写、翻译转载及较长正文后部差异可能漏判，共用模板也可能误报。复用库中存储不等于本任务多了一份独立来源。

## 两层资料

1. **稳定基础库**：来源和版本明确、可以离线使用的关键卷章。当前评测基线固定为原有六份古籍卷章及两份百科摘录；同一批实验中不加入新资料。
2. **按需补充库**：根据问题缺口，通过外部目录查找具体卷章，读取正文并保存固定修订、来源、许可说明及哈希，再由索引 worker 建立向量。以后可以复用这些资料，无需每次重新下载整本书。

扩充顺序可先补齐《通鉴》卷217至222这一组相关时段，再按失败问题引入两唐书的相关人物篇章。不要按卷数宣传覆盖率，也不要猜测其他列传的卷号。新增资料后使用新评测批次，避免把新增语料的收益误认为 Agent 循环收益。

## 已实现的获取路径

- 资料库中的“按需查找”使用中文维基文库官方 REST API；不需要聊天模型，也不要求 Tavily Key。
- 只查询最多五个候选页面；用户选择一页后才导入正文。目录摘要不作为历史证据。
- `/page/{title}/with_html` 返回实际卷章标题、修订号、正文及许可；保存为带 `oldid` 的固定版本链接。读取固定修订使用 `/revision/{id}/with_html`。
- 已保存的固定版本可从 MySQL 复用；可变的最新页面仍重新读取。相同正文通过哈希去重，重复导入不会增加片段和向量。
- 通用研究默认使用 DeepSeek Search / Fetch，分别配置工具地址与可选独立 Key；聊天 Key 可复用，但聊天接口本身不会自动搜索。Tavily 保留为可选服务。设置 `SEARCH_PROVIDER=wikisource` 时只检索中文维基文库，界面明确提示站点范围；不能称为通用互联网搜索。
- 固定修订与哈希解决的是可追溯性，不能保证转录正确或多个来源独立。原文仍需要校勘。

官方契约见 [MediaWiki REST API](https://www.mediawiki.org/wiki/API:REST_API/Reference) 和 [API 使用政策](https://www.mediawiki.org/wiki/API:REST_API/Policies)。2026-10-20 本机主机请求超时，Docker 内目录与指定卷章读取成功；部署网络和主机网络的结果不能混为一谈。

## 权利与可靠性

古籍原作与现代数字转录、标点、校注、译文具有不同权利边界。维基文库 API 返回的许可和固定页面应随快照保留，贡献者可通过该页历史记录查看；重新分享转录文本时保留署名与相同方式共享要求。不能把“古籍”理解为任何网站上的点校或译文都可批量复制。

本版不做递归全站爬取，不绕过登录、付费、验证码或抓取限制。其他站点优先采用官方接口、可下载授权数据，或者用户自行取得的 TXT/Markdown/JSON。没有明确许可的现代论文仅保留链接，等待合法导入；现代研究资料仍是当前缺口。

手动网页导入与非 DeepSeek 读取使用受限 HTTP 客户端：公网 DNS 校验、IP 固定、逐跳重定向校验、体积与时间上限。DeepSeek Fetch 是服务端代理读取，提交前本地验证 HTTP/HTTPS、端口及初始域名公网地址，提供商负责后续解析及重定向安全；本项目无法固定其连接 IP 或核对所有跳转。其响应另有限时、限体积与结构校验。页面里的指令不改变 Agent 权限。

全网抓取保存正文后立即可在本次任务中阅读，不等待向量索引。在线 P2 将「研究快照」与「主动收藏」分开：新快照只保留原文与片段，不自动建立向量；在引证、已读网页或文献详情收藏后，才由后台索引并参与以后的本地混合检索。手动导入与加入专题也算主动收藏。索引失败保留原文，详情提供原因和重试，收藏操作不会阻塞原研究。不能把暂时没有向量的网页误称为没有读到正文。

研究专题按人物、事件、地区组织文献与历史任务；分类标签由用户填写，不自动冒称识别出历史实体。限定专题研究会固定当时已就绪的全部文献 ID；要求1–30份，空专题或未索引资料不会改查全库。全网研究仍只查本次搜索获得的网页，不因收藏或专题而默认混入旧材料。取消收藏、移出专题都保留历史证据；快照目前无自动清理，覆盖面与磁盘维护仍需人工管理。

## 用评测指导扩充

每次阅读失败案例时记录三个问题：缺相关卷章，还是已经命中但没读，或读到了仍解释错误？只有第一类优先加史料。其余分别修检索/工具选择与回答审核，避免用不断增加语料掩盖系统问题。

优先收集十到三十份能回答专题核心问题的完整卷章，再逐步扩大主题。这个数量是维护起点，不是系统限制，也不代表已经覆盖全部史源。近似转载和共同史源仍需人工辨析。
