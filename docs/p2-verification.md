# P2：逐项核查、失败诊断与用量透明

更新：2026-10-20。已完成本地部署、单题真实 DeepSeek 回归、引用阅读和导出验证。保留所有已知失败，不将这些观测扩展为整体历史准确率。

## 已实现

- 原文先释读，再对候选表述的主语、数量、时间、否定与因果逐项核查。第一步只提供实际引文，不提供候选结论。第二步使用同一模型，仍可能共同误解古文，不是独立证据。
- 子句必须来自候选原句，证据 ID 必须属于该条实际引文，要求覆盖重要事实；不能用整体“支持”覆盖子句“不支持”。缺失、重复、越界和未读证据均有程序级拒绝测试。提示包含已知生日错误提醒，属于针对性回归，不能称盲测收益。
- 结构化错误每任务最多修正一次，记录阶段、字段、错误类型和结束原因。明确 Answer.premise 必须是 Claim 对象，不能是字符串。保持校验，不将畸形回答强行转换成成功。
- 已有通过审核的部分结果时，若后续答案修订因格式错误或预算中断，保留已核查结果并说明修订未完成。新草稿不会替代它。此恢复分支由测试替身验证；最终真实任务没有触发该分支。
- 每次模型请求保存输入、输出、合计 Token、请求序号、已观测累计和缺失 usage 次数。worker 将 model_usage 事件写入 MySQL，再通知 WebSocket；断线后可回放。未返回用量时明确未知，不填零。returned 仅表示响应返回，不代表审核通过。
- 默认每模型实例最多16次请求；已返回 usage 累计60000后阻止下一次请求。当前请求可越过该阈值，且不覆盖其他进程，所以不是人民币硬预算。普通评测默认最多计划3条，90条批次需显式指定。
- 失败页展示可回放诊断与用量；正式回答可展开逐项核查，点击引用显示准确高亮、原文释读、上下文、版本和保存时来源。Markdown 导出只读已有记录，不调用模型；逐条校验摘录、偏移和来源关联。
- local 评测支持固定资料 manifest 的ID与正文哈希。新资料可以保留，但不会混进指定的旧基线范围。本轮未付费重跑30题三方案。

## 部署与验证边界

Docker Desktop首次启动因Inference Manager及Secrets Engine的旧Unix socket无法访问而退出。退出崩溃进程后，仅改名备份两个socket运行目录，再启动恢复；镜像、数据库、索引卷和配置未重置。备份名含p2-backup-20261020-200118。没有恢复出厂设置，也没有删除持久化卷。

最终镜像使用缓存的锁定依赖做离线增量构建，强制重新安装项目包，随后部署API、worker和index-worker。MySQL、Redis、Milvus、etcd、MinIO与API健康，11份资料均ready。完整无缓存构建仍未重验，不能把本次增量部署称为全新环境安装通过。最终镜像和代码哈希见 [p2-manifest.json](p2-manifest.json)。

完整测试中曾有3项Tavily单元测试继承机器的wikisource环境，误发外网并超时；已显式固定其搜索提供方。最终全套 **89 passed，37.61秒**，包括2项真实中间件集成测试；模型使用明确替身，真实模型另由上述任务验证。中间件测试使用独立shijian_test库、Redis DB1和独立Milvus集合。最终容器22个源码与安装包文件哈希一致，Ruff、JS语法和引用导出检查通过，机器可读结果在manifest。

本轮没有P2全量30题复评、独立人工评分或最终版本联网回答端到端复验。保留P1归档与失败案例，人工分数仍为空。程序定位、模型逐项支持判断与历史真实性是不同层次，不能互相替代。

本轮新增生产改动约120行，主要为逐次用量事件、结构化约束和修订失败保留；其中约35行为格式/预算/恢复边界。测试、评测脚本与文档另计。未新增模型角色或服务。
