# P0：回答质量与研究效率

更新：2026-10-19。本轮使用真实 DeepSeek、MySQL 原文及 Milvus/BGE 检索；模型配置来自环境，没有测试替身冒充真实回答。账户请求已恢复成功。

## 修复与边界

- 研究阶段使用 required 工具选择，停止由证据评估、预算和停滞检测控制，避免模型在尚未阅读原文时用普通文本提前结束。仍由模型选择查询、片段和后续方向，不是固定 RAG。
- 规划仅携带最新完整工具交换、当前评估、证据短预览及已完成操作；生成只提供去重后的原文；审核只携带实际引用的原文和必要字段。原文、相邻关系和服务端引用定位不受压缩影响。
- 明确书名的本地查询按繁简规范化后的真实标题匹配资料范围；最后一轮有未读命中时只开放阅读，避免搜索出结果却没有时间读。
- 成功的相同工具调用复用结果。连续两轮无新增证据/线索停止，失败不伪装为成功缓存，尝试仍计入工具上限。
- 引用或支持审核导致核心答案缺失、前提被拒绝时，最多修订一次，再完整审核；不降低逐字摘录或已读证据要求。
- 适配器对结构化输出为空/格式错误做每任务最多一次格式修正，仍不符合协议则失败。该次数与答案修订分别记录，受总超时约束，不自动重试认证/余额错误。
- 自由文本“限制”也纳入内容支持审核，记录未展示的限制条目；这仍是模型辅助审核，不能保证消除全部语义错误。
- 任务状态 completed 只表示执行结束。结果新增 answered / partial / insufficient_evidence / incomplete，前端显示证据覆盖状态，旧任务不追溯补造新状态。
- 记录每次模型请求的阶段、耗时、上下文字符数及实际 Token 用量；字符数不包含工具 schema，不能当作 Token。调用未返回 usage 时该次用量为 null；费用保持 null。

代码净增约 300 行生产逻辑（含约 60 行预算、格式及结果校验，按职责估算），实际比初始计划多出格式修正、限制审核与书名范围控制；对应新增来自真实失败和测试，不新增服务或模型角色。

## 真实 worker 与 WebSocket

本地 Docker 镜像已重建并部署。任务 `1e0b5ad5-ad8f-42ea-a6cd-315d71ab7805` 在真实 worker 中执行，WebSocket 收到三条事件后断开，任务继续完成。重连回放 57 条事件；18 个引用的正文、URL、原始全文偏移逐项核对通过。任务结果为 partial，正确指出已读材料中的冲突涉及安庆绪，未宣称穷尽史料。

此额外任务耗时 **65.306 秒，96,778 Token**，读取 20 段证据，包含一次格式修正和一次答案修订。它说明复杂问题仍可能很贵，当前仅有轮数、工具、证据量和超时硬上限，**没有每任务总 Token 硬预算**。不能把五题总量下降当成所有任务都低消耗。后续如需严格成本上限，应把格式修正/答案修订预留和可用答案保留一起设计，再评测质量代价。

本次 live smoke 显式跳过再次创建取消任务，取消和失败语义由真实基础设施集成及其他回归覆盖。[实时协议记录](live-smoke.json)、[实际页面](p0-result.jpg)。

## 验证与复现

最终完整测试：**60 passed，0 skipped，30.45 秒**，包括两项真实 MySQL/Redis/Milvus/BGE 集成测试；其余模型协议和分支测试使用清楚标注的夹具。Ruff、JS 语法与 Docker 构建通过。测试不等于模型内容语义正确。

```sh
# 需要可用模型账户、真实数据库/向量库及已缓存的 BGE：
uv run --extra embedding python -m eval.p0 --output eval/runs/p0-new
# 对已有记录生成对比，不调用模型：
uv run python -m eval.p0 --report-only --output eval/runs/p0-new --baseline eval/runs/p0-before-live
# 实际调用模型，验证跨进程任务、引用与断线回放；默认还另建取消任务：
uv run --extra embedding python scripts/smoke_live.py --skip-cancel
```

独立测试库配置方式见 README；未配置 TEST_DATABASE_URL 时集成测试跳过，不能报全通过。本次真实测试沿用独立 shijian_test 库、Redis DB 1 和独立向量集合。

工具选择参数按 [DeepSeek Chat Completions 官方说明](https://api-docs.deepseek.com/api/create-chat-completion/)核对：非 thinking 模式支持 required；继续显式禁用 thinking。结构化输出的 include_raw 及绑定实现核对了本机锁定版本 LangChain 源码与 [官方接口](https://reference.langchain.com/python/langchain-deepseek/chat_models/ChatDeepSeek/bind_tools)。
